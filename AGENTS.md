# Правила для агентов, работающих в этом репозитории

Этот файл читают агенты Hermes (и Claude Code / Codex) при работе в репо.

## Ветки (gitflow)

- `main` — только релизы. Прямые коммиты запрещены.
- `develop` — интеграционная ветка. Сюда вливаются фичи.
- `feature/<номер-задачи>-<краткое-имя>` — от `develop`, одна задача = одна ветка.
- `hotfix/<краткое-имя>` — от `main`, для срочных правок.
- `release/<версия>` — подготовка релиза.

## Обязательные правила

1. **Никаких коммитов в `main` и `develop` напрямую.** Только через PR.
2. **Один PR = одна задача** из трекера. В заголовке PR — ID задачи.
3. **Тесты обязательны.** Новая функциональность без теста не принимается.
4. **CI должен быть зелёным** перед запросом ревью.
5. **Перед изменением архитектуры — ADR** в `docs/adr/`.
6. **Не менять чужие файлы «попутно»** — отдельная задача, отдельный PR.
7. Секретов в репозитории нет. Ключи — только в переменных окружения / GitHub Secrets.

## Что делать перед завершением задачи

- [ ] Тесты проходят локально
- [ ] Линтер чистый
- [ ] PR создан, описание заполнено
- [ ] Задача в трекере переведена в «на ревью»
