# ADR-0001: Gitflow и CI в GitHub Actions

- **Дата:** 2026-10-21
- **Статус:** принято
- **Контекст:** нужен предсказуемый процесс разработки для проектов, которые ведут агенты под контролем владельца. Сервер Hermes имеет 1.9 ГБ RAM и без root — локальный CI невозможен.

## Решение

Используем gitflow (`main` / `develop` / `feature/*` / `hotfix/*`), обязательные PR с зелёным CI, а CI/CD выполняем в GitHub Actions.

## Почему

- Защищённые ветки + обязательный PR дают точку контроля перед попаданием кода в основную линию.
- Actions не нагружают сервер Hermes и работают на инфраструктуре GitHub.
- История линейная и читаемая: легко понять, какая задача что изменила.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Trunk-based (все в main) | Нет барьера для ошибочного кода агента |
| Github-flow (main + feature) | Меньше изоляции релизов; gitflow привычнее для параллельных агентов |
| Локальный CI на сервере | 1.9 ГБ RAM, нет root, нет Docker |

## Последствия

- Плюс: ревью и тесты — обязательный шлюз.
- Минус: больше церемоний (ветки, PR) — для мелких правок ощутимо.
- Требуется, чтобы у токена GitHub были права `repo` и `workflow`.
