# ADR-0002: Как обеспечиваем gitflow без платного плана GitHub

- **Дата:** 2026-10-21
- **Статус:** принято
- **Контекст:** нужен технический запрет на прямые коммиты в `main` и `develop`. GitHub не даёт ни branch protection, ни rulesets для приватных репозиториев на бесплатном плане (HTTP 403: «Upgrade to GitHub Pro or make this repository public»).

## Решение

Двухуровневая защита, бесплатная:

1. **Глобальный git-хук `pre-push`** на сервере Hermes (`~/.git-hooks/pre-push`, включён через `git config --global core.hooksPath`). Отклоняет любой `git push` в `refs/heads/main` и `refs/heads/develop`. Обход только осознанный: `ALLOW_PROTECTED_PUSH=1 git push`.
2. **Workflow `Guard (gitflow)`** — при пуше в `main`/`develop` проверяет через GitHub API, связан ли коммит с Pull Request. Если нет — падает красным и пишет причину в лог.
3. **Настройки репозитория** (работают и на бесплатном плане, проверено): разрешён только squash-merge, `merge commit` и `rebase` запрещены, ветка удаляется после мерджа. Так история остаётся линейной без платной защиты.

## Почему так

- Все агенты работают с одного сервера Hermes, поэтому клиентский хук здесь — реальный барьер, а не формальность.
- Guard-workflow даёт видимый след: прямой пуш останется красным в истории Actions.
- Ноль затрат и ноль новых систем.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| GitHub Pro ($4/мес) | Владелец решил пока не платить; включается в один клик позже |
| Сделать репо публичными | Открывает код; не подходит для рабочих проектов |
| Только дисциплина агентов | Не барьер: агент может ошибиться |

## Ограничение на будущее: одобрение ревью

При одном GitHub-аккаунте требование «минимум одно одобрение» заблокирует все мерджи — GitHub запрещает одобрять собственный PR. Поэтому скрипт по умолчанию ставит 0 одобрений; `REQUIRED_APPROVALS=1` имеет смысл только после появления второго аккаунта с правом записи (например, отдельного аккаунта для роли «ревьюер»).

## Последствия

- Плюс: прямые пуши в основную линию физически невозможны с этого сервера.
- Минус: хук не действует, если репозиторий клонируют на другой машине — там защита только через guard-workflow (красный CI после факта).
- Если позже подключим GitHub Pro — branch protection включается скриптом `scripts/setup-branch-protection.sh` без переделок.
