# ADR-0003: Публичные репозитории и нативные правила веток вместо хуков

- **Дата:** 2026-10-21
- **Статус:** принято (заменяет ADR-0002)
- **Контекст:** в ADR-0002 защита gitflow обеспечивалась самодельными слоями — глобальным git-хуком `pre-push` и workflow `Guard`. Владелец решил, что приватность репозитория сейчас не требуется, а лишние механизмы мешают работать: хук действует на все репозитории сервера и требует обходов, `Guard` шумит в истории Actions.

## Решение

Репозитории держим **публичными**, защиту веток делаем **штатными средствами GitHub** — ruleset `gitflow` для `main` и `develop`:

- изменения только через Pull Request (прямой пуш отклоняет GitHub);
- обязательная проверка `Lint & tests` на актуальной версии ветки;
- запрет force-push и удаления ветки;
- требование разрешить обсуждения в PR;
- мердж только squash, ветка удаляется автоматически.

Настройка одной командой: `./scripts/setup-repo-rules.sh`.

## Почему так

- На публичных репозиториях защита веток и rulesets бесплатны — платить не нужно.
- Правила действуют на любой машине и с любого устройства: это делает сам GitHub, а не наш хук.
- Минус один: код проектов виден всем. Владелец подтвердил, что для текущих задач это приемлемо.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Приватный репо + хук и guard (ADR-0002) | Два самодельных слоя, хук действует на все клоны сервера, guard шумит; работает только «на нашей стороне» |
| Приватный репо + GitHub Pro ($4/мес) | Тот же результат без публичности, но платно — пока не нужно |

## Последствия

- Удалены: `.github/workflows/guard.yml`, `scripts/pre-push`, глобальный `core.hooksPath` на сервере, `scripts/setup-branch-protection.sh`.
- Прямой пуш в `main`/`develop` невозможен ни с одной машины — включая эту.
- Если позже понадобится приватность: делаем репозиторий приватным и подключаем Pro тем же скриптом (для приватных rulesets недоступны на бесплатном плане).
- Требование одобрений оставлено 0: при одном аккаунте GitHub запрещает одобрять свой PR. Появится второй аккаунт — правим в ruleset.
