# Процесс разработки

Конвейер от идеи до релиза. Три точки контроля владельца помечены 👤.

```
Идея (голос/текст)
   │
   ▼
1. Спецификация  ── spec-документ, критерии приёмки   👤 утверждение
   │
   ▼
2. Архитектура   ── ADR: компоненты, стек, почему      👤 утверждение
   │
   ▼
3. Декомпозиция ── задачи на доске + зависимости
   │
   ▼
4. Разработка    ── ветка feature/*, код + тесты
   │
   ▼
5. Контроль      ── CI: линт + тесты (автомат)
   │
   ▼
5a. Ревью кода   ── ревьюер: качество, риски, безопасность
   │
   ▼
5b. Приёмка      ── тестировщик: критерии приёмки, edge cases, доказательства
   │
   ▼
6. Merge в develop
   │
   ▼
7. Релиз         ── develop → main, тег, changelog     👤 добро
```

## Роли агентов

| Роль | Что делает | Выход |
|---|---|---|
| Оркестратор | ведёт задачу от спеки до релиза, держит доску | задачи, отчёты |
| Архитектор | ADR, схема компонентов, выбор технологий | `docs/adr/NNNN-*.md` |
| Разработчик | код + тесты в ветке | Pull Request |
| Ревьюер | читает diff: качество кода, риски, безопасность, соответствие ADR | комментарии, вердикт |
| Тестировщик | проверяет поведение против критериев приёмки из спеки, ищет краевые случаи | отчёт с доказательствами, баги |

## Границы ролей: ревьюер и тестировщик — это разные роли

- **Ревьюер** отвечает на вопрос «код сделан правильно?» — читает diff, ищет риски, нарушения архитектуры, дыры в безопасности.
- **Тестировщик** отвечает на вопрос «задача действительно решена?» — проверяет поведение против критериев приёмки, воспроизводит краевые случаи и обязан приложить доказательства: команды и их реальный вывод, а не суждение.
- Зелёный CI означает лишь, что написанные тесты проходят. Он не доказывает, что задача решена, поэтому приёмка — отдельный шаг.

## Критерии «задача готова»

- Все критерии приёмки из спеки выполнены и проверены
- Тесты написаны и зелёные в CI
- PR смерджен в `develop`
- Документация обновлена (README / docs / ADR)
